# Connected media: DigiBot + Provenance Lens

DigiBot and the [Provenance Lens browser extension](https://github.com/Blimp3/provenance-lens-extension) share one admitted account. Connected mode is controlled by the `INTEGRATION_ENABLED` Worker variable, and the steps below use the Lens 1.0.0 popup labels. Existing owners may create single-use invitations with `/invite`. Invited users receive ordinary connected-media access plus exactly one downloader capability: a page link sent from Lens, delivered only to their own linked chat. They get no Telegram downloader commands and no operator views. Public signup is closed.

## Use it

1. Open Lens Settings → Connect DigiBot → Start pairing. Send the displayed `/link` command in your private bot chat, compare the code, approve, and complete pairing in Lens.
2. In the Lens popup, choose **Verify an image on this page** for a Check or **Pick an image to download** for a Download, then click the image. A Check records provenance evidence, and a Lens Check saves the checked file as a Telegram document. Download sends the file without calling the verifier.
3. On the phone, send an image to the bot and tap **Check this image** under it, or reply `/check` to the image. PNG, JPEG or WebP up to 4 MiB; HEIC is not supported. Send the image as a File to preserve its bytes: a Telegram photo is recompressed and loses its Content Credentials, so it is checked as a Telegram photo copy and its reply says so; the service cannot recover an earlier original that Telegram did not provide. The verdict, or the processing error, is replied under the image and kept in `/history`. No copy of the image is sent back: the image you sent stays in the chat as its saved copy, which `/history` shows confirmed and verified because the checked bytes came from that message, or an earlier saved copy of the same bytes is reused. The bot prompts under every image it receives, captioned or not; a caption never starts a check. Every tap on one prompt is the same single check, while a `/check` reply and a button tap on the same image are separate checks. The button is removed after any tap. It works for 24 hours; after that, or when Telegram no longer shows the image under the prompt, a tap answers "Reply to the image with /check". Only checks started in Telegram are replied in the chat; Lens-started checks report in Lens and `/history`, and a `/checkretry` run or a check recovered by the scheduled repair reports only in `/history`.
4. Use `/history` or the Mini App's **Connected history and stats** link (the **Shared history and stats** view) for shared History. `/checkstats [24h|7d|30d|all]` shows the same account totals as Lens.
5. In the Lens popup, choose **Check audio or video segment**, select **Video URL segment**, and enter a supported video URL and an explicit range. Only the extracted MP3 segment is checked. It does not check video frames or the whole source and does not create an audio Download.
6. On a page from a supported source, choose **Send this page's link to Telegram** in the Lens popup. Lens sends only the active tab's link (**Pick a video on this page** sends the link you click instead, such as an X post's own status link) over its connected session and never fetches or uploads the video. DigiBot checks the link with the same rules as a link pasted in the chat and queues the same download: video up to 1080p, or M4A audio for YouTube Music. Lens can also ask, in the **Send to Telegram as** dropdown above the button, for one of three outputs: **Video** (the default above), **MP3** (the same job as `/audio URL mp3`) or a **Clip**, an integer start and end in seconds within 24 hours (`0 <= start < end <= 86400`) that trims the video at the 1080p ceiling (only a ceiling: the height is chosen so the whole source fits under 49,000,000 bytes, so a clip of a longer video arrives at a lower height) with no quality picker (or the M4A on YouTube Music); the API also trims an MP3 when output mp3 comes with a range; the popup does not offer an MP3 clip. The queue notice and the result arrive in your own Telegram chat, which is the only status channel. A result over 49,000,000 bytes arrives there as a private download link that expires after one hour.

No supported provenance signal is not proof of human origin. Valid signatures, file binding, signer trust and signed AI declarations are separate evidence. General AI/deepfake classifiers and video-frame analysis are outside this release.

## Limits and data handling

| Input | Limit |
| --- | --- |
| Image Check | PNG, JPEG, WebP; 4,194,304 bytes; HEIC is not supported |
| Audio Check | Supported file contents; 4,194,304 bytes; measured duration up to 60 seconds |
| Video segment | Integer start/end, forward range up to 60 seconds within 24 hours; MP3 output; reject unavailable/clamped ranges |
| Independent Download | At most 49,000,000 bytes; Telegram document delivery |
| Lens link download | One supported page link per action, under the Telegram chat's source and URL rules. Leave output out for video (1080p ceiling; M4A on YouTube Music) or send `mp3`; an optional clip adds integer `startSeconds` and `endSeconds`, `0 <= start < end <= 86400`. One bound alone, a non-integer, an empty or inverted range or one beyond 24 hours is refused. Invited accounts: 5 per hour. Owners: the Worker's hourly job limit (20 in `wrangler.jsonc`), shared with their Telegram jobs. Everyone: at most 5 unfinished jobs. Queued in the single download/captions lane shared with Telegram jobs (one active download). Link downloads do not count toward account admission below |
| Account admission | 20 actions/hour; 4 retained inputs; 98,000,000 reserved temporary bytes |
| Pair/session | Pairing 5 minutes; access 15 minutes; rotating refresh 7 days; absolute session lifetime 30 days |

Checks send the exact admitted input to the existing OpenAI Content Provenance API and run the supported embedded Content Credentials check. [OpenAI states that content provenance checks are not eligible for Zero Data Retention](https://developers.openai.com/api/docs/guides/content-provenance); its processing/retention rules apply independently of Telegram and this app. Media does not exist only in Telegram during processing.

Image Checks preserve the checked file in Telegram: a Lens Check as a document the bot sends, whose matching retrieved SHA-256 marks its integrity verified, and a Telegram Check as the image message you sent, verified by the bytes fetched from it. Downloads larger than Telegram's hosted getFile limit can have confirmed delivery without a verified round-trip hash. Audio Checks are not automatically archived. R2 and extension outbox bytes are temporary: retry access expires after 24 hours, successful processing removes unneeded copies earlier, and scheduled cleanup retries physical removal. A separate 1-day bucket lifecycle rule is an additional backstop. Container scratch workspaces are removed by the existing context manager; abandoned workspaces use the existing 24-hour startup sweep.

A link download is an ordinary DigiBot job, not a Lens action, so it does not appear in Lens History or `/history`; it counts under **Legacy downloads** in `/checkstats` and the Mini App stats. Like a link pasted in the chat, its job row keeps the page URL only encrypted, plus a keyed hash for duplicate detection, and the encrypted URL is cleared when the job completes or fails. Its structured log lines carry the job ID, source host, that hash and operational fields, never the URL or Telegram identifiers.

Authoritative History remains until deleted. Local Lens retention settings apply to standalone results only. Workflow steps contain opaque account/action IDs and normalized evidence, never media bytes, provider credentials or source URLs. Encrypted source URLs are cleared when extraction succeeds or retry expires. Minimal deleted-action tombstones remain for 30 days; stale browser registration timestamps cannot recreate them afterward. Integration Workflow state expires one day after completion or error. [Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/) can retain execution metadata for up to seven days, and [D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/) retains database recovery history for up to 30 days on the Paid plan (seven on Free). These platform copies are distinct from active-app deletion.

## Failure and deletion behavior

A retry keeps the same user action and increments a processing generation. Provider attempts are counted separately and capped at three for an action. A completed result is checkpointed before History persistence and remains independent of cache-write or Telegram delivery failures. A fresh Check can reuse the account's cached evidence while still adding its own History row and saving a missing original.

Telegram has no upload idempotency key. A lost send response is **unknown**, never an automatic resend. Reply to the document actually sent by this bot with `/reconcile ACTION_ID`; the bot verifies the account, sender and file hash before recording the receipt. `/checkretry ACTION_ID` performs only a permitted controlled retry. An expired or irrecoverable input requires a new intentional action with the exact file.

Resending the same link-download action returns the same job, and the same action with another link, output or clip range is refused with `operation_conflict`. A rejected link (`invalid_url`, `unsupported_source`), a bad output or range (`invalid_request`) or a full limit (`job_limit`) queues nothing, and the error response carries a short message for Lens to show. An owner account whose Telegram ID was removed from `ALLOWED_TELEGRAM_USER_IDS` keeps its Lens session and its other connected-media access but gets `forbidden` for link downloads, as Telegram ignores that user's download commands.

**Delete History**, **Delete media**, **Clear cache**, and **Delete saved Telegram copy** are separate controls. **Delete saved Telegram copy** removes only a document the bot sent as a saved copy; for a copy recorded as sent by you it refuses with `not_found` and says that the copy stays in Telegram, so the bot never deletes your own message. A `/check` reply to a document the bot sent earlier records that document the same way unless its bytes already have a saved copy. App deletion does not promise removal of Telegram/provider/downloaded copies. Telegram can refuse deletion of older messages; the UI reports that separately. A delete never authorizes replay of an ambiguous send.

## Rollout order and rollback

Roll out in this order, with `INTEGRATION_ENABLED` false throughout: additive D1 migrations 0020 and 0021, Lens's compatible `IntegrationVerifier` named entrypoint, the reviewed downloader Container image, then the gateway and `IntegrationWorkflow`. Turn the flag on last. Both Workers must belong to the same Cloudflare account, because the verifier is a service binding. The verifier Worker is not part of this repository; `wrangler.jsonc` names it `example-lens-verifier` as a placeholder. `wrangler.jsonc` pins the exact `chrome-extension://` origins in `INTEGRATION_ALLOWED_ORIGINS`; no wildcard origin, caller account header or shared ZIP token authorizes connected access.

A successful local test or readiness response is not proof of deployment or Telegram delivery. Verify a real Telegram byte round trip, account isolation and source limits before treating the feature as live.

Disable new admission for rollback; retain additive tables, receipts and unknown delivery states. Never reset or blindly replay operations.
